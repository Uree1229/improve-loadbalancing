# CPU 로드밸런싱 실험 결과 v1~v24

2026년 11월 16일 v1~v3 재측정 100회를 반영했다. 원본 커널과 직접 비교한 실험, 같은 커널에서 기능만 바꾼 실험, Windows 호스트 정책을 바꾼 실험은 각각의 대조군을 기준으로 읽는다.

| 비교 | 확인한 결과 |
| --- | --- |
| 커널 코드 효과 | 호스트를 고정한 180회에서 **v18 커널**의 200ms 복구 중앙값이 인접 원본보다 **97.5~98.2% 감소**했다. |
| 초기 후보 재측정 | **v1·v3**의 200ms 중앙값은 두 원본보다 낮았다. 835ms 관측 최댓값은 v1~v3 모두 두 원본보다 높았다. |
| Windows 정책 효과 | **v23 정책**은 같은 v18 커널의 두 부팅에서 세 목표를 모두 통과했다. v24는 v23 대비 추가 개선 기준에 미달했다. |

복구 지연은 affinity 제한을 풀고 네 vCPU에 분산된 것으로 관측되는 상태가 50ms 유지되는 구간의 시작점까지다. 아래에서 **해제 시작 기준**은 affinity 확대 호출에 걸린 시간을 포함한다. v4~v8의 초기 집계는 **해제 완료 기준**이고 표본 p90을 사용한 평가도 있었다. 관측 최댓값은 해당 반복 중 가장 큰 값이다. `pinned-256`은 256 KiB 작업이 계속 CPU0에 고정된 대조군이다. **호스트 CPU 시간**과 **게스트 실행시간**을 구분했다. 짝비교 변화율은 반복별 `(후보/대조 − 1) × 100`의 중앙값이다.

## v1~v3 · 고정된 호스트에서 원본 커널 대조

같은 C 바이너리와 v23 Windows 전원 정책으로 원본 → v1 → v2 → v3 → 원본을 각각 새로 부팅했다. 부팅당 200ms 계열 8회(유지 136~257ms), 835ms 8회, pinned-256 4회로 총 **100회**다. 복구 지연은 해제 시작 기준이다.

| 커널 | 변경 | 200ms 중앙값 (ms) | 835ms 최댓값 (ms) | pinned-256 호스트 CPU 중앙값 (s) |
| --- | --- | ---: | ---: | ---: |
| 원본 1 | 프로젝트 기준 이미지 | 103.87 | 270.80 | 10.41 |
| [v1](../versions/v1/) | newly-idle hotness 기준 확대 | **73.47** | 345.50 | **10.09** |
| [v2](../versions/v2/) | runnable 수 조건 추가 | 107.59 | 299.92 | 10.31 |
| [v3](../versions/v3/) | runnable 작업이 있을 때 hotness 기준 축소 | 76.88 | **285.33** | 10.23 |
| 원본 2 | 프로젝트 기준 이미지 | 92.17 | 269.46 | 10.25 |

굵은 값은 v1~v3 후보 중 최솟값이다. v1의 200ms 중앙값은 원본 두 부팅보다 20.3~29.3%, v3는 16.6~26.0% 낮았다. v3의 835ms 최댓값은 원본 대비 14.53~15.87ms 높았다. 후보별 부팅은 한 번이다. 이전 steady·bursty 결과와 별도로 집계했다.

정식 100회, reference·warmup 포함 계산 출력 135개, 독립 호스트 기록 200개를 검증했다. 첫 시도는 Windows 전원 설정 조회 시간 초과로 정식 측정 전에 중단됐다. 조회 방식을 수정한 재시도에서 전체 순서를 완료했다.

## v4~v8 · 초기 원본 커널 대조

200·800ms 계열의 복구 중앙값을 같은 실험의 인접 원본과 비교했다. 범위는 후보 부팅과 인접 원본 부팅의 비교에서 나왔다. 이 시기 일반 작업 비용은 실행시간이나 idle balance 시도율로 기록했다.

| 커널 | 변경 | 전체 정식 횟수 | 200ms / 800ms 복구 중앙값 변화 | 비용·재현 결과 |
| --- | --- | ---: | --- | --- |
| [v4](../versions/v4/) | pinned backoff 상한 512 → 32 | 139 | 재검증 **−54.8~−43.1% / −57.3~−53.6%** | bursty-1024 실행시간 +9.1~12.5%, 고정 작업의 idle balance 시도율 약 6.7~7.5배 |
| [v5](../versions/v5/) | affinity 확대 시 NOHZ 요청 | 205 | 추가 부팅 **−7.1% / +0.02%** | 첫 부팅의 큰 감소가 재현되지 않았다. 초기·추가 비교는 실행 맥락도 달랐다. |
| [v6](../versions/v6/) | 대상 CPU의 irq_work와 로컬 복구 | 205 | **−97.8~−95.9% / −98.7~−93.0%** | 후보 두 부팅에서 복구 단축. bursty-256과 steady 비용 기준 일부 미달 |

초기 비교의 부팅별 상세값과 비용 항목은 [v4~v9 종합 기록](CPU_load_balancing_overall_comparison_20261106.pdf)에 있다.

## v9~v18 · 동일 커널 이미지의 기능 비교

v9는 복구 기능 전체의 OFF/ON이다. v10~v16은 기존 제어를 실험별로 맞춘 상태에서 해당 버전의 추가 기능을 OFF/ON 했다. v17·v18은 같은 이미지에서 세 상태를 비교했다. 표의 값은 기능 ON 또는 해당 후보 상태에서 관측했다. 200ms는 조건명이고, 긴 조건의 실제 유지시간은 **v9 740~835ms**, **v10~v16 739~857ms**, **v17~v18 835ms**였다. 지연은 해제 시작 기준이다.

| --- | --- | ---: | ---: | ---: | --- |

| [v10](../versions/v10/) | idle이 유지될 때 제한 재시도 | 72 | 3.81 | 63.05 | 두 지연 기준 미달 |

v9의 범위는 세 부팅의 조건별 집계 범위다. v10~v16은 추가 기능 상태마다 복구 조건별 8회, v17·v18은 세 상태 각각 복구 조건별 8회였다. 판정에는 표의 두 값 외에도 각 파일럿에서 정한 조건별 지연·비용 기준을 적용했다.

### v18 · 같은 호스트 설정에서 원본 커널과 별도 비교

v23 Windows 정책을 양쪽에 고정하고 원본 → v18 → 원본 → v18 → 원본 순서로 **180회** 측정했다. 인접 원본의 200ms 중앙값 **80.48~85.45ms**에 비해 v18은 **1.57~2.02ms**, 835ms 관측 최댓값은 원본 **261.46~295.13ms**, v18 **2.09~2.45ms**였다. pinned-256 호스트 CPU 시간 변화는 짝비교 중앙값 **−1.46~+0.78%**였다. 사전 기준 48개를 통과했고, 일반 작업 중 실행시간 최대 +3.77%, 호스트 CPU 시간 최대 +3.09% 증가한 조건도 있었다. ## v19~v24 · v18 커널에서 Windows 호스트 정책 비교

표에 있는 복구 지연은 해제 시작 기준이다. 200ms 계열 중앙값은 **같은 부팅의 v18 대조 정책**과 비교한다. 835ms 열은 v19부터 이후 실험의 대조군으로 사용한 코어 파킹 해제 정책과 비교한다. pinned-256 열은 해당 부팅 내 v18 정책 대비 호스트 VM CPU 시간의 짝비교 중앙값 변화다. v19 행의 두 지연 지표는 모두 같은 부팅의 v18 정책이 기준이다.

| --- | --- | ---: | --- | --- | ---: | --- |
| [v19](../versions/v19/) | 코어 파킹 해제 | 108 | 5.29 → **2.47** | 25.75 → **4.72** | +6.98% | pinned CPU 비용 기준 미달 |

| [v24](../versions/v24/RESULTS.md) | v23에 두 등급 최소 성능 하한 100% 추가 | 144 | 2.69 → **1.98** | 2.83 → **2.26** | −27.08% | 기본 목표 통과. 같은 부팅의 v23 대비 추가 개선 기준 3개 모두 미달 |

v19의 세 번째 상태는 v18 이미지에서 v17 기능 수준을 재현한 대조군이다. 표는 v18 상태와 v19 정책을 대조한다. v22의 단일 실행 CPU 시간 최댓값은 첫 부팅 24.63초, 재부팅 17.84초였다. v23에서 연결 오류로 중단된 29회는 완료된 216회에 포함하지 않았다. v24는 재부팅 재현을 진행하지 않았다. 같은 부팅의 v23 대비 200ms 중앙값은 **1.92 → 1.98ms**, 835ms 최댓값은 **2.31 → 2.26ms**, pinned-256 CPU 시간 변화는 **−0.39%**였다. [v22 세부 결과](../versions/v22/RESULTS.md) · [v23 재현 집계](../versions/v23/RESULTS.json) · [v24 판정](../versions/v24/RESULTS.md)

공통 목표를 적용한 v22~v24에서는 200ms 중앙값이 v18 대조 정책보다 낮고, 835ms 관측 최댓값은 v19 대조 정책 대비 +1ms 이내이며, pinned-256 CPU 시간 변화는 v18 대조 정책 대비 +5% 이내여야 했다. 이 결과의 범위는 Windows·VirtualBox의 해당 4 vCPU VM과 affinity 제한 해제 벤치마크다. [기존 그래프와 지표 정의](PERFORMANCE.md)
