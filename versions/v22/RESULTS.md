# v22 비교와 재현

같은 Windows 호스트와 Ubuntu VM에서 v18, v19, v22를 부팅당 108회씩 비교했다. 세 조건 모두 v18 게스트 커널을 사용하고 Windows 전원 설정을 바꿨다. 각 부팅에서 200ms와 835ms는 조건당 8회, `pinned-256`은 조건당 4회 측정했다.

| 측정 | 지표 | v18 | v19 | v22 |
|---|---|---:|---:|---:|
| 첫 부팅 | 200ms 복구 지연 중앙값 | 2.75 ms | 2.25 ms | 2.03 ms |
| 첫 부팅 | 835ms 복구 지연 관측 최댓값 | 23.94 ms | 3.25 ms | 2.57 ms |
| 첫 부팅 | `pinned-256` 호스트 VM CPU 시간 중앙값 | 10.97 s | 12.79 s | 10.72 s |
| 재부팅 | 200ms 복구 지연 중앙값 | 3.00 ms | 2.01 ms | 1.79 ms |
| 재부팅 | 835ms 복구 지연 관측 최댓값 | 8.04 ms | 2.90 ms | 2.65 ms |
| 재부팅 | `pinned-256` 호스트 VM CPU 시간 중앙값 | 12.72 s | 15.70 s | 15.62 s |

200ms 중앙값은 두 부팅 모두 v18보다 낮았다. 835ms 관측 최댓값은 두 부팅 모두 v19보다 낮았다. `pinned-256`은 반복별 v22/v18 CPU 시간 비율의 중앙값으로 판정했다. 첫 부팅은 -3.98%, 재부팅은 +20.24%였으므로 +5% 이내 기준은 재현 시험에서 미달했다.

v22의 단일 실행 CPU 시간 최댓값은 첫 부팅 24.63초, 재부팅 17.84초였다. 같은 VM에서 얻은 관측값이며 835ms 최댓값은 표본의 최대치다.
