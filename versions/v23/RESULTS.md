# v23 비교와 재현

같은 v18 게스트 커널에서 Windows 설정을 v18 기준, v19 기준, v23 조건으로 교차 비교했다. 새 부팅 두 번에서 각각 108회씩 완료했다. 아래 v18·v19·v23 표기는 호스트 설정 조건이며 세 조건의 Linux 커널 이미지는 같다.

| 측정 | 지표 | v18 설정 | v19 설정 | v23 설정 |
|---|---|---:|---:|---:|
| 첫 부팅 | 200ms 복구 지연 중앙값 | 2.244 ms | 2.404 ms | 1.558 ms |
| 첫 부팅 | 835ms 복구 지연 관측 최댓값 | 5.361 ms | 4.100 ms | 2.103 ms |
| 첫 부팅 | pinned-256 VM CPU 시간 중앙값 | 10.023 s | 9.734 s | 9.727 s |
| 재부팅 | 200ms 복구 지연 중앙값 | 2.668 ms | 2.319 ms | 1.710 ms |
| 재부팅 | 835ms 복구 지연 관측 최댓값 | 11.408 ms | 3.175 ms | 2.328 ms |
| 재부팅 | pinned-256 VM CPU 시간 중앙값 | 14.273 s | 14.508 s | 10.023 s |

pinned-256의 반복별 v23/v18 CPU 시간 비율 중앙값은 첫 부팅 -4.44%, 재부팅 -23.37%였다. 두 부팅 모두 세 사용자 기준과 추가 19개 기준을 통과했다. 부팅 사이에는 기준 조건의 CPU 시간도 크게 달라졌으므로, 각 부팅 안의 비교로 판정했다.

첫 재현 시도는 호스트 종료 마커의 연결 오류로 29/108회에서 중단됐다. 이 부분 실행은 따로 보존하고 집계에 섞지 않았으며, 새 부팅의 108회 전체 결과를 재현 결과로 사용했다.

이 결과는 같은 VM에서 관측한 호스트 설정 효과다. Linux 코드 자체의 원본 대비 효과는 [고정 호스트 커널 비교](../../experiments/fixed-host-kernel-ab-20261108/)에서 별도로 확인했다.
