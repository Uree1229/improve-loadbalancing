# Windows 호스트 고정 조건의 커널 비교

고정된 Windows 호스트 설정에서 프로젝트 원본 커널과 v18 수정 커널을 비교했다. 두 수정 부팅 모두 CPU affinity 제한 해제 후 분산 복구 지연이 앞뒤 원본보다 줄었고, 사전 판정 48개를 모두 통과했다.

원본은 5.4.214-lb-base, 수정은 5.4.214-lb-v18이다. 같은 C 소스와 바이너리, GCC 9.4.0을 사용했고 커널 설정 차이는 LOCALVERSION뿐이었다. 모든 부팅에 v23 호스트 정책을 유지했다.

| 부팅 | 커널 | 200ms 복구 중앙값 | 835ms 복구 관측 최댓값 | pinned-256 VM CPU 시간 중앙값 |
|---|---|---:|---:|---:|
| 원본 1 | lb-base | 80.478 ms | 295.133 ms | 10.180 s |
| 수정 1 | lb-v18 | 2.024 ms | 2.446 ms | 10.008 s |
| 원본 2 | lb-base | 85.445 ms | 261.463 ms | 10.156 s |
| 수정 2 | lb-v18 | 1.573 ms | 2.085 ms | 10.109 s |
| 원본 3 | lb-base | 83.574 ms | 293.103 ms | 10.055 s |

수정 1은 원본 1·2와, 수정 2는 원본 2·3과 각각 비교했다. 200ms 중앙값 감소율은 97.5~98.2%였고, pinned-256 CPU 시간의 짝비교 중앙값 변화는 -1.46~+0.78%였다. 일반 작업의 짝비교 중앙값은 실행시간이 최대 +3.77%, CPU 시간이 최대 +3.09% 증가했다.

복구 지연은 affinity 확대를 시작한 시점부터 네 CPU에 분산된 관측 상태가 50ms 유지되는 구간의 시작점까지다. 확인용 50ms를 지연에 더하지 않는다. CPU 샘플 기반 지표이며 매 순간의 동시 CPU 점유를 직접 추적한 값은 아니다.

각 부팅에서 복구 조건은 8회씩, 일반 조건 다섯 개는 4회씩 측정했다. 원본→수정→원본→수정→원본의 새 부팅 5회에서 정식 180회, reference·warmup 포함 계산 출력 215개와 독립 호스트 기록 360개를 검증했다. 호스트 설정은 첫 재부팅 전부터 마지막 측정까지 같은 상태로 유지했고 306개 감시 표본의 최대 간격은 7.719초였다.

200ms 조건은 기존 시험과 같은 136·143·166·184·190·191·250·257ms의 hold를 사용했다. recovery-800이라는 내부 조건 이름의 실제 hold는 835ms다. 전체 실행 순서와 사전 기준은 [protocol.json](protocol.json), 부팅별 집계와 모든 짝비교는 [results.json](results.json)에 있다.

이 결과는 이 VM과 고정 호스트 정책에서 affinity 제한 해제 후 복구 속도가 개선됐음을 보여준다. 수정 커널 두 부팅의 재현이며 범용 CFS 성능이나 모든 작업의 실행시간 개선을 뜻하지 않는다. 원본은 보관된 프로젝트 기준 이미지로, 이번 시험에서 upstream을 새로 빌드한 이미지는 아니다.

원본 커널 복귀와 Windows 전원 설정·VM 스케줄링 설정 원복, 임시 경로 및 수집기 종료를 확인했다. 커널 소스와 독립 패치는 [v18](../../versions/v18/)에 있다.
